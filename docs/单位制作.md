# 植物 / 僵尸单位制作流程

> 本文档说明在本项目中**新增或扩展**一个可上场棋子（植物 / 僵尸）的标准流程。  
> 与 `@requirement-workflow` 的关系：**简单换皮 / 数值微调** 可按本文直接做；**新机制、Boss、跨模块技能** 须先走需求卡片与审批（见文末）。

**关联 Context**：`context/modules/Chess.md`、`context/modules/Skill.md`、`context/architecture/decisions.md`

**关联设计文档**：[plant-deckbuilding-design.md](game-design/plant-deckbuilding-design.md)（构筑 / 体系 / 肉鸽分档 — **策划定稿 plant 定位时先读**）

## 0. 流程总览

```
需求澄清（可选 @requirement-workflow）
    ↓
策划定稿（定位、数值、技能、动画、羁绊）
    ↓
美术资源（Sprite / Reanim / 特效 / 音效）
    ↓

    ↓

```

## 2. 策划定稿清单（动手前必填）

在 Unity 里建资源前，先明确：

| 项 | 植物 | 僵尸 |
|----|------|------|
| **阵营** | `Player` | `Enemy` |
| **chessName** | 全局唯一，与存档/图鉴/羁绊 ID 一致 | 同左 |
| **定位** | `PlantType`（MainPlant / SupportPlant / …） | 波次 `waveLimit`、`PassesWavePoolFilter` |
| **种植/站位** | `TileType`、`IPlantFunction`（`MainPlant` / `SupportPlant` 等） | 出场格、`FindTileMethod` |
| **基础属性** | 血量、价格、冷却、攻速等 `Property` | 同左 |
| **攻击** | `Weapon` 序列化类型（近战/射击/样本格等） | 同左 |
| **技能** | 主动 `ISkill` + 被动 `ISkillEffect` 列表 | 同左 |
| **动画来源** | 单 Sprite 序列 / **Reanim 多部件** / Spine,动画上添加死亡/技能/攻击事件 | 同左 |
| **接入点** | 植物商店、关卡 `cards`、奖励 `AwardPanel` | `LevelData.zombieList`、僵王召唤池等 |

## 3. 目录与命名规范

| 资源 | 路径 |
|------|------|
| **棋子 Prefab** | `Assets/Prefab/ChessPrefab/[分类文件夹]/[chessName]/[chessName].prefab` |
| **PropertyCreator（植物）** | `Assets/Resources/ChessData/Player/[chessName].asset` |
| **PropertyCreator（僵尸）** | `Assets/Resources/ChessData/Enemy/[chessName].asset` |
| **技能脚本** | `Assets/Script/Skill/ISkillEffect_Plant/` 或 `ISkillEffect_Zombie/`、`ISkillPassive/` |
| **动画** | Prefab 同目录下 `动画/` 子文件夹，或 `Assets/Reanim2UnityAnim/Output/` |
| **Shader 材质** | 默认 `Assets/Shader/BaseShader/BaseMaterial.mat`（受击闪烁等） |

**注意**：脚本目录为 `Assets/Script/`（单数），不是 `Scripts`。

## 4. 美术资源

### 4.1 简单单位（单 Sprite + Animator）

1. 准备 **idle / attack / skill / death** 等序列帧或 Animation Clip。  
2. 图标 `chessSprite`：用于商店、图鉴、种子包 UI。  
3. 可选：种植预览图、卡牌 Prefab 用图。

### 4.2 PVZ Reanim 单位（多部件僵尸/植物）

1. 将 `.reanim` 与贴图放入 `Assets/Reanim2UnityAnim/reanim_all/`（或沿用已有资源，见 `docs/Reanim2UnityAnim-inventory.md`）。  
2. 菜单 **`Window → Reanim2UnityAnim`**：  
   - 选择 `.reanim`  
   - 配置 `center`、分段 `customPartitions`（idle、walk、attack、death 等）  
   - 点击 **生成** → 输出到 `Assets/Reanim2UnityAnim/Output/[单位名]/`  
3. 生成结果挂到 Prefab 子层级（多 `SpriteRenderer` / 骨骼名如 `arm`、`head`）。  
4. 分部件换皮（如僵王）：在自定义 `AnimatorController_*` 上配置多组 `Sprite`，见 `docs/requirements/僵王分部件贴图.md`。

### 4.3 特效与音效

- 技能特效：优先 **预制体 + 对象池** 或粒子 Prefab 放在 `Assets/Resources/Effect/`。  
- 音效：经 `AudioManage` / 棋子 `AudioPlayer`（按现有单位引用方式）。

### 方式 B：复制现有单位（推荐机制相近时）

1. 复制最接近的 Prefab 文件夹与 `PropertyCreator.asset`。  
2. 重命名 `chessName`，全局替换引用。  
3. 修改 `PropertyCreator` 与 Prefab 上 `SkillController` / `AttackController` 的序列化字段。

### PropertyCreator 核心字段

```text
chessName / chessSprite / chessDescription / chessEffect
baseProperty（Property：hp、price、cd、waveLimit…）
chessPre → 指向本单位 Chess Prefab
plantType / chessTileType / plantFunction（植物）
plantTags / fetterMemberId（羁绊）
PlantCardPre / PlantEntrepotCardPre（植物商店 UI，可选）
```

`PropertyCreator.chessPre` **必须**指向带 `Chess` 组件的 Prefab，否则 `CreateChess` 无法实例化。

## 6. Prefab 组件检查表

根物体 **Chess** 上序列化模块（与现有单位保持一致）：

| 模块 | 职责 |
|------|------|
| `PropertyController` | `creator` → 本单位 PropertyCreator |
| `SkillController` | `activeSkill` / `passiveSkill`（`[SerializeReference]`） |
| `AttackController` | `weapon` |
| `MoveController` | `tileMethod`（`FindTileMethod`） |
| `StateController` | `stateGraph`（Idle/Attack/Skill/Death） |
| `BuffController` | 默认即可 |
| `AnimatorController` 子类 | 绑定 `sprite`、`animator`；特殊僵尸可继承 `AnimatorController_Zombieking` 等 |

**技能实现约束**（必读 `.cursor/rules/unity-skill-no-runtime-monobehaviour.mdc`）：

- **禁止**为技能 `AddComponent` 运行时专用 MonoBehaviour。  
- 使用 **`ISkill` / `ISkillEffect`** + `WhenEnterGame` / `OnRemove` / `SkillContext` / 协程 `user.StartCoroutine`。  
- 参考：`PassiveSkillEffect_MinerZombie`、`ISkillEffect_BigRabbit`。

**动画事件**（在 Animation Clip 上）：

- 普攻伤害：`Chess.TakeDamage()`  
- 技能生效：`Chess.UseSkill()` → `SkillController.UseSkill()`  
- 死亡收尾：状态机进 `DeathState` 后 `Chess.Death()`（回收）

**<u>下一步做动画</u>** 

![image-20260526110534318](C:\Users\admin\AppData\Roaming\Typora\typora-user-images\image-20260526110534318.png)

点击sprite在Inspector面板 有个SpriteRender组件。这个组件就是显示这个单位长什么样子的组件。sprite就是要显示的图片样式，我们把Project里的单张图片拖入，那么这个单位的默认长相就是对应的图片了。帧动画的原理就是每间隔1/12秒修改一次spriteRender的sprite,图片的切换就形成了动画。Color是图片颜色，因为我们图片是上好色的所以默认是白色就好；Flip是朝向，因为我们默认所有图片朝向是向右，然后如果你的角色画的朝向是向左的，那你就点一下这个Flip。同理，因为僵尸图片默认也是向右的，但他在生成的时候会被y轴旋转至朝左就不需要改Flip。但是如果图片是朝左的就需要点这个Flip。反正图片是朝左的就点Flip。

AdditionalSetting里面只有Sortinglayer和OrderInLayer需要考虑。Sortinglay表示渲染层级，层级越高渲染优先级越高。同层级下OrderInLayer越高 渲染顺序越高。这个我在代码里有设置 所以不用手动修改。

切换到attack动画后，点击addProperty 意思是这个动画时间轴里面你有哪些属性是需要随时间改变的。因为我们的动画是挂载在Chess(蜘蛛).prefab下面的 而我们的图片（spriteRender组件）是放在sprite子物体上的。所以我们要添加sprite->SpriteRender->Sprite。按shift+滚轮可以拉到右边 点击加号就可以把对应属性放到时间轴上。

这里解释一下为什么不把SpriteRender直接放在chess上，因为我动画和角色行为是分离的。比如说一个僵尸他的动画是大跳砸地，如果他的动画也放在角色本体上，那他大跳的时候可能就到其他行了，就会被其他行的植物打到，但他实际的判定位置应该是要在原本行的。同理还有我想让这个角色在生成的时候他的脚能站在对应的草地的中心，或者说我希望同行的所有植物都站在统一条线上。那么他们本体的chess的transform.position.y应该是一样的。但是你图片有大有小 有正有歪，你可能实际放进去发现设置y为零的时候脑袋在草坪中心。这是不符合视觉效果的。那如果是分离的情况 就可以直接修改子物体的sprite的位置 让他对准，就不会影响chess的判断逻辑的情况下，让视觉逻辑也正常，还有很多其他好处就不一一说明了。**重点就是要知道动画改变的是(子物体sprite)的(spriterender(组件)的sprte（组件对象）)**

**AttackFuntion:武器的攻击方式**

![image-20260526141530387](C:\Users\admin\AppData\Roaming\Typora\typora-user-images\image-20260526141530387.png)

就是chess是怎么攻击敌人的。最常用的是CloseAttack和ShootBullet；CloseAttack就是直接造成伤害；ShootBullet就是发射子弹。一般的僵尸都是CloseAttack

![image-20260526141653836](C:\Users\admin\AppData\Roaming\Typora\typora-user-images\image-20260526141653836.png)

设置为CloseAttack后，Effect是不用配置的,这个是某些攻击会生成一些特效的时候我留的接口，一般用不上；然后DM主要是设置DamageType和DamageElement 一个是攻击类型，就是物理魔法真伤这种；另一个是攻击属性，就是伤害是爆炸（无视防御），切割（会切割绳子），穿刺（会击破气球），碾压（如果目标体型小于自身则秒杀对方）

TargetEffect.SelftEffect：也是生成特效的，只不过这个特效一个是生成在自身位置，一个是生成在地方位置。

interval：攻击间隔：一般是用在攻击动画帧数小于实际攻击间隔的时候使用。一般来说攻击动画attack直接设置为loop就可以了。但是有时候我想让他的攻击间隔很长，但是我动画可能就画了8帧，那我可以让attack播完后先播放idle动画。然后经过interval时间后他会再次播放attack动画。一般情况不设置就行。

AttackOver:这个是内部逻辑 不用管

**棋子定位类型**：主要是植物有这个区别 这个比较复杂，一般的植物都是MainPlant 视为主植物，一个草地格只能有一个主植物。SupportPlant辅助植物是可以种植在主植物上的植物，比如南瓜罩。一个主植物只能拥有一个辅助植物；PotPlant花盆植物，睡莲花盆等可以改变地形的植物。一个草地格只能拥有一个花盆植物；Consume：消耗品 如咖啡豆，可以直接种植在植物上有特殊效果，使用完就消失；LimitType:有特殊限制的植物（比如可种植数量，场上必须有某些单位等）。僵尸一般选None就行
**种植方式**：根据不同的定位类型选择对应的种植方式。一般植物选择MainPlant；然后还有升级植物必须种植在基础植物上；limit植物只能种植一个等；僵尸的话一般选NonePlant;

## 8. 注册到游戏

### 8.1 加入全局卡池 `GameManage.allChess`

1. 打开场景 **`Assets/Scenes/开始.unity`**（或挂有 `GameManage` 的入口场景）。  
2. 在 `GameManage` 组件的 **`allChess`** 列表中追加本单位 `PropertyCreator`。  

用途：图鉴、`Test` 模式、`PlantsShop` 兜底卡池、部分查找 `GetCreatorByChessName`。

### 8.2 植物：商店与选卡

| 接入 | 做法 |
|------|------|
| **植物商店选卡** | `PreParePlugun_ShowPlantShop.cards` 填入 PropertyCreator；或依赖 `playerOwnedCreators` |
| **玩家拥有** | 存档 `ownedCreatorIds`；`AwardPanel.Win()` / 金币商店 `ShopItemEffect_Creator` |
| **种子 UI** | 配置 `PlantCardPre`、`PlantEntrepotCardPre` |

### 8.3 僵尸：关卡出怪

1. 在 **`Assets/Resources/LevelData/`** 下打开目标 `LevelData` asset。  
2. 配置 **`zombieList`** / 波次相关字段（与 `LevelController` 生成逻辑一致）。  
3. 确认 `waveLimit`、`PlantType.LimitType` 等池化规则（`PropertyCreator.PassesWavePoolFilter`）。  

测试面板：`TestScenePanel` 会从 `Resources/ChessData/Player` 与 `Enemy` 加载列表。

## 11. 常见问题

| 现象 | 排查 |
|------|------|
| 关卡刷不出 | `LevelData` 是否引用；`waveLimit` / 池过滤 |
| 商店没有 | `allChess` / `playerOwnedCreators` / `PreParePlugun_ShowPlantShop.cards` |
