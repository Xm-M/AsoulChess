# 会话管理器

## 目的

提供完整的会话管理能力：
1. 会话开始时恢复状态、加载上下文、选择任务
2. 会话结束时更新进度、提交代码、生成总结
3. 支持长时间运行的开发任务
4. 管理会话历史记录

## 使用场景

**开始会话**：
```
@session-manager start
需求: [需求ID]
功能: [可选，指定功能ID]
```

**结束会话**：
```
@session-manager end
需求: [需求ID]
提交: [true/false]
```

**查看会话历史**：
```
@session-manager history
需求: [需求ID]
```

## 会话生命周期

```
会话开始
    ↓
恢复开发状态 (@progress-recovery)
    ↓
选择开发功能
    ↓
加载功能上下文
    ↓
记录会话开始
    ↓
[开发工作进行...]
    ↓
会话结束
    ↓
更新功能状态 (@progress-tracker)
    ↓
更新进度文件
    ↓
Git 提交（如指定）
    ↓
生成会话总结
    ↓
记录会话结束
```

## 会话开始流程

### 步骤1：接收会话开始请求

```
@session-manager start
需求: inventory-system
```

### 步骤2：恢复开发状态

**调用**：@progress-recovery

**获取信息**：
- 整体进度
- 已完成/进行中/待开始的功能
- 上次会话记录
- 推荐开发的功能

### 步骤3：功能选择

**策略**：
1. 如有进行中功能 → 询问是否继续
2. 如无进行中功能 → 推荐优先级最高的可开发功能
3. 如用户指定功能 → 验证依赖满足后确认

**输出**：
```

需求: inventory-system
时间: 2026-04-02 14:00

- 整体进度: 33% (2/6)

- 进行中: 无
- 待开始: 4个功能

🔥 INV-002: 物品拖拽功能

选择:
[1] 开发 INV-002 (推荐)

[3] 查看功能列表
```

### 步骤4：加载上下文

## 会话结束流程

### 步骤1：接收会话结束请求

```
@session-manager end
需求: inventory-system
提交: true
```

### 步骤2：收集会话信息

**统计信息**：
- 会话持续时间
- 开发的功能
- 生成的代码文件
- 遇到的问题

### 步骤3：更新功能状态

**调用**：@progress-tracker update

**更新内容**：
- 功能状态: `in_progress` → `completed`
- 实际工时
- 完成时间

### 步骤4：更新进度文件

**添加会话记录到 progress/[需求ID].md**

### 步骤5：Git 提交（可选）

**如指定 `提交: true`**：
```bash
# 自动执行
git add .
git commit -m "feat(inventory): complete item drag functionality

- Add ItemDragHandler.cs
- Implement drag and drop logic
- Add visual feedback during drag
- Tested with 8x5 grid layout

Related feature: INV-002"
```

**提交信息格式**：
```
<type>(<scope>): <subject>

<body>

Related feature: <功能ID>
```

## 长时间运行支持

### 上下文压缩

**场景**：会话过长，接近上下文限制

**策略**：
1. 总结已完成功能的上下文
2. 保留当前功能的完整上下文
3. 将历史上下文转为摘要

### 子会话管理

**场景**：一个功能需要多会话完成

**处理**：
1. 记录子会话（同一功能ID，不同会话ID）
2. 累积进度
3. 最终标记完成

---

## 最佳实践

### 1. 会话粒度

**推荐**：
- 每次会话 2-4 小时
- 完成 1-2 个功能
- 定期提交代码

### 2. 会话中断处理

**策略**：
- 正常中断：更新状态为 `in_progress`，记录进度
- 异常中断：下次恢复时询问是否继续

### 3. 代码提交

**建议**：
- 每个功能完成后提交
- 提交信息包含功能ID
- 保持提交粒度适中
