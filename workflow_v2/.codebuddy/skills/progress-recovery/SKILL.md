# 进度恢复器

## 目的

提供进度恢复能力，支持：
1. 恢复开发状态（已完成/进行中/待开始）
2. 识别可开发的功能（依赖满足）
3. 推荐下一个开发的功能
4. 重建开发上下文

## 使用场景

**恢复开发状态**：
```
@progress-recovery
需求: [需求ID]
```

**检查可开发功能**：
```
@progress-recovery check
需求: [需求ID]
```

## 工作流程

```
接收恢复请求
    ↓
读取功能列表
    ↓
读取进度文件
    ↓
分析功能状态
    ↓
识别依赖满足的功能
    ↓
推荐下一个功能
    ↓
生成恢复报告
```

## 功能选择算法

### 推荐优先级

| 优先级 | 条件 | 权重 |
|--------|------|------|
| 1 | 进行中功能（完成度 < 100%） | 100 |
| 2 | P0 优先级 + 依赖满足 + 关键路径 | 90 |
| 3 | P0 优先级 + 依赖满足 | 80 |
| 4 | P1 优先级 + 依赖满足 + 阻塞其他功能 | 70 |
| 5 | P1 优先级 + 依赖满足 | 60 |
| 6 | 可并行开发的功能 | 50 |

### 依赖检查

```
功能可开发条件:
1. 状态为 not_started
2. 所有 requires 依赖的功能状态为 completed
3. 无阻塞标记
```

### 并行开发检测

```
功能A和功能B可并行条件:
1. 功能A和功能B无相互依赖
2. 功能A和功能B修改的文件不冲突
3. 功能A和功能B属于不同 parallel_group
```
